# Sewall.ai source integration reference

Documentation checked September 10, 2026. This document distinguishes published interfaces from proposed Sewall.ai adapters. Reading documentation does not establish working credentials, endpoint availability, approved research use, institutional agreements, or provider commitments. The first implementation should retrieve bounded public metadata and retain authoritative source links.

## Source matrix

| Source and scale | Documented interface | Access and reuse conditions | Proposed adapter and scientific limits |
| --- | --- | --- | --- |
| NCBI GenBank: nucleotide sequences and genetic context | Entrez Nucleotide supplies sequence identifiers and annotations; E-utilities supports programmatic retrieval. Pin accession versions and explicit sample references. [GenBank overview](https://www.ncbi.nlm.nih.gov/genbank/) | NCBI places no GenBank data-use restriction, but submitters may assert intellectual-property rights. Verify the selected records and intended products. Public sequence access does not authorize access to separately controlled genotype data. | Proposed bounded sequence-metadata and source-supported sample-link adapter, not implemented by the present live metadata MVP. GenBank sequences are not automatically sample genotype calls. Use genotype or diversity summaries only where suitable existing records and verified specimen/population, place and time links support them. Otherwise retain taxon-level context. |
| Encyclopedia of Life (EOL): taxonomy, traits, ecological interactions, images | Classic search/pages APIs; structured data API with Cypher queries over a property graph; reconciliation at `https://eol.org/api/reconciliation`. [EOL data services](https://www.eol.org/docs/what-is-eol/data-services) | EOL states that the structured API requires a key and that clients must follow query limits. A single taxon page can contain multiple licenses. Preserve rights and attribution for each item. [EOL copyright policy](https://eol.org/docs/what-is-eol/copyright-and-linking-policy) | Proposed taxon reconciliation and trait provenance adapter. Taxonomic similarity does not establish sample identity. Trait presence on a species page does not establish the trait of a field individual. The live adapter remains unvalidated. |
| NCBI GEO: functional genomics studies | E-utilities `db=gds` retrieves descriptive/accession metadata; `db=geoprofiles` serves expression profile records. Full records and files require a separate retrieval from GEO file services. [GEO programmatic access](https://www.ncbi.nlm.nih.gov/geo/info/geo_paccess.html) | Public GEO records require no login. NCBI imposes no GEO reuse restriction, but submitters can assert intellectual property rights. [GEO FAQ](https://www.ncbi.nlm.nih.gov/geo/info/faq.html), [GEO disclaimer](https://www.ncbi.nlm.nih.gov/geo/info/disclaimer.html) | Public metadata discovery can be implemented first. Preserve GSE, GSM, GPL, Entrez UID, organisms, linked publications, and source versions where present. Metadata discovery is not expression analysis. A GEO accession alone does not establish paired genotype, field location, or outcome. |
| NCBI public variation: human reference variants | RefSNP JSON through `https://api.ncbi.nlm.nih.gov/variation/v0/refsnp/{rsid}`. [NCBI Variation Services example](https://ncbiinsights.ncbi.nlm.nih.gov/2019/10/07/dbsnp-celebrates-20-years/amp/) | Public reference variant descriptions are distinct from controlled participant genotypes. The service has not been called in this documentation review. | Proposed reference-variant metadata adapter. Do not treat an rsID as an individual's genotype. dbSNP ceased supporting new non-human variation and removed it from interactive services in 2017. Non-human ecological genotype studies therefore need another documented source. [NCBI notice](https://www.ncbi.nlm.nih.gov/books/NBK431021/) |
| NCBI dbGaP: study metadata and controlled human genotype/phenotype data | Public study pages, dictionaries, and summaries; separate Authorized Access workflow for controlled data. [dbGaP overview](https://www.ncbi.nlm.nih.gov/projects/gap/cgi-bin/about.html) | A qualified investigator requests study-specific access. The institutional Signing Official co-signs; the NIH Data Access Committee decides. [NIH access procedure](https://www.grants.nih.gov/policy-and-compliance/policy-topics/sharing-policies/accessing-data/dbgap) | Prototype only the policy workflow using fictional records. Agents may compare terms and draft a request. They cannot sign for an institution, grant access, or treat a successful negotiation as authorization. No controlled retrieval is proposed for the initial MVP. |
| NCBI PubMed: literature and study context | ESearch and ESummary with `db=pubmed`; EFetch for records; ELink for documented repository links. Endpoint family: `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/`. [E-utilities introduction](https://www.ncbi.nlm.nih.gov/books/NBK25497/) | Rate limits are 3 requests/second without a key and normally 10 with a key. PubMed abstracts can be copyrighted. Make the NCBI disclaimer evident to users. | Public citation discovery first. Record PMID, source URL, query, retrieval time, and available study links. A paper discussing a species is a literature connection, not proof of a matched biological sample or unrestricted full-text rights. |
| Google AlphaEarth Foundations Satellite Embedding V1: landscape context | Earth Engine collection `GOOGLE/SATELLITE_EMBEDDING/V1/ANNUAL`. Current catalog: 2017 through 2024, 10-meter pixels, 64 annual embedding dimensions. The catalog also documents a Cloud Storage distribution. [Dataset catalog](https://developers.google.com/earth-engine/datasets/catalog/GOOGLE_SATELLITE_EMBEDDING_V1_ANNUAL) | Dataset license is CC BY 4.0 with specified attribution. Earth Engine client use needs credentials and an authorized, registered Cloud project. Dataset licensing and platform access are separate. [Authentication guide](https://developers.google.com/earth-engine/guides/auth), [Earth Engine access](https://developers.google.com/earth-engine/guides/access) | Proposed compute-to-data spatial summary adapter. Capture year, location uncertainty, geometry, projection, scale, masks, and model/dataset versions. Learned dimensions are not individual physical measurements. Annual layers cannot resolve daily events. No Google credits, quotas, collaboration, or project credentials are assumed. |

EOL verification has a specific limitation: its official data-services and terms pages were visible through the search index, but direct retrieval returned HTTP 403 during this review. The documented API descriptions above come from those indexed official pages. Before implementing EOL retrieval, verify the current endpoint schema, account/key process, query limits, and applicable content rights. Do not use the discontinued experimental JSON-LD attribute service. [EOL data services](https://www.eol.org/docs/what-is-eol/data-services)

For AlphaEarth-derived outputs, preserve this catalog-required attribution: “The AlphaEarth Foundations Satellite Embedding dataset is produced by Google and Google DeepMind.” Pin the collection and observed `DATASET_VERSION` and `MODEL_VERSION`; check coverage on each run. The catalog's exclusive end date of January 1, 2025 does not establish availability of a 2025 layer. [Dataset catalog](https://developers.google.com/earth-engine/datasets/catalog/GOOGLE_SATELLITE_EMBEDDING_V1_ANNUAL)

## Integration rules proposed for the prototype

These are design requirements inferred from the source boundaries above, not capabilities promised by the providers.

1. Represent links explicitly as `same_sample`, `same_taxon`, `same_study`, `cites`, or `spatial_context`. Record the evidence, method, uncertainty, and reviewer. Never promote a weaker relation into a sample match.
2. Require explicit location and collection-time evidence before a landscape join. A laboratory address or author affiliation is not a sampling location. Record missing or ambiguous coordinates as a failed eligibility check. Preserve temporal mismatch rather than silently substituting another year.
3. Keep source assertions separate from derived claims. A successful API response means retrieval succeeded. It does not validate experimental design, causal interpretation, taxonomic reconciliation, or statistical independence.
4. Store small manifests, policy profiles, provenance, and permitted derived materializations. Dispatch expensive work to an authorized data-side environment when source policy, transfer costs, or privacy require it. Do not mirror source holdings by default.
5. Treat data-use negotiation as a structured process: inspect terms, compare the intended use, propose permitted compute or output alternatives, draft questions, and wait for documented decisions from authorized people. Unresolved permission produces a pending state. Denial or revocation blocks dependent work.
6. Separate metadata discovery, retrieval permission, scientific eligibility, execution, validation, and release. A model-generated plan can suggest actions; deterministic checks enforce the current permission and evidence requirements before each action.

## Readiness and acceptance evidence

| Adapter class | Minimum evidence before calling it working |
| --- | --- |
| PubMed and GEO public metadata | A bounded live query with dated source responses; accession parsing; respectful throttling; provenance; honest empty/error handling; no credentials in logs. Apply one shared rate budget when multiple workers share an NCBI IP or API key. |
| GenBank sequence and genetic context | A bounded metadata retrieval with accession versions and explicit sample-link evidence. Separate reference sequences, descriptive genotype attributes, variant annotations and validated genotype calls. No sample-level ecological feature without verified biological, spatial and temporal compatibility. |
| EOL | Verified key/access arrangements, current response examples, retained item-level licensing, and reviewed taxonomic ambiguity. Until then, label fixtures as fictional examples. |
| Public genotype/variation | Name the actual database and organism scope; distinguish variant annotations from participant-level genotypes; verify assembly and identifier semantics. A biodiversity pilot needs independently verified non-human genotype accessions and reuse conditions. |
| AlphaEarth | Authorized project or another verified permitted interface; a small spatial query; recorded coverage, units/representation, versions, attribution, compute cost, and returned bytes. |
| Controlled sources | Institutional authorization and an approved execution environment, plus revocation and egress checks. The initial MVP demonstrates these states with fictional policy fixtures only. |

Persist an interface status such as `documented`, `configured`, `live_validated`, or `unavailable` independently of each scientific claim's evidence status. Passing local fixture tests establishes prototype behavior, not live federation or scientific validity.
