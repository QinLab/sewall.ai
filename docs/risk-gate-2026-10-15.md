# Gated release risk assessment (October 15, 2026)

`sewall/riskgate.py` decides, output by output, what a finished run may release. It follows the
release-gating argument of Acharya, Al Amin and Qin, "Structure Before Intelligence: Gating What
Agentic Scientific Workflows Release" (arXiv:2610.19507), and scores risk the way a reliability
engineer runs a failure mode and effects analysis (FMEA).

## How it works

The gate reads a manifest and, optionally, a peer-review forum record from `sewall forum`. It runs
five stages:

| Stage | Check | Effect of a failure |
|---|---|---|
| G0 integrity | `verify_agent_manifest`; `verify_forum` against the same manifest | Every output blocked |
| G1 run status | safe_stopped or failed blocks; budget_exhausted or needs_review holds | Applies to every output |
| G2 containment | Quarantined or blocked graph nodes | That output blocked; the rest still assessed |
| G3 peer review | Unresolved forum concerns attach to the outputs they cite | Concerns enter G4 as failure modes |
| G4 risk | Fixed catalog of 16 failure modes, RPN = S x O x D | Hold, release with limitations, or release |

Each active failure mode carries a severity (S), an occurrence (O) taken from the evidence (for
example, the share of readings older than two hours) and a detection rating (D) for the harness's
existing controls. An output that no review post cites gets D raised by one. Only concern and
limitation posts and replies that answer a concern count as review; a support or agree post does
not lower D. A forum concern counts as resolved only when an answer cites run evidence that the
concern did not already cite, and an agree reply leaves it contested. An output is held when any mode reaches RPN 150, or S 8 or more with O 6
or more. It is released with limitations from RPN 20. The run's result is assessed last as an
output that depends on all the others, and it is held whenever any of them is held.

There is no override input. An agent or reviewer can change a decision only by producing evidence
the gate reads, such as a new run, a concern, or an answer that brings new run evidence. `risk-gate-verify` recomputes the record from
its inputs and rejects any edit.

```bash
python3 -m sewall risk-gate output/RUN/manifest.json [--forum output/FORUM/forum.json] --out DIR
python3 -m sewall risk-gate-verify DIR/risk-gate.json output/RUN/manifest.json [--forum ...]
```

Peer review changes the York outcome in the way the design intends. Without a forum, every monthly
NDCI summary is held. Once reviewers have discussed them, the summaries are released with
limitations. The result stays held because one major concern is still contested.

## Limitations

The S and D ratings and the thresholds are prototype settings chosen by hand and have not been
calibrated against observed failures. An RPN ranks outputs for attention; it is not a probability
that an output is invalid. The catalog covers only the failure modes this prototype knows about. A
release decision applies to retrieved evidence. The gate validates no biological claim.
